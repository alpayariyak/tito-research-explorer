01 / THE MISMATCH

Two ways to remember.

A token is a piece of the model’s vocabulary, identified by a number. Different token sequences can decode to the same readable text.

ATHE EXISTING ROLLOUT

Keep a token tape

Keep the model’s original token IDs. Append its action and the tool’s reply. The next call inherits that exact tape.

PromptSampled actionTool result→
next = prompt ⧺ action ⧺ observation
BTHE DEPLOYMENT WE WANT TO MATCH

Rebuild from messages

Store text and tool calls as messages. Apply the chat template and tokenize the whole conversation again for the next call.

Messages→Template→New token IDs
next = tokenize(template(history))
Why not just retokenize the training data too?+

A sampled token has a probability under the prompt and action prefix that produced it. Replacing those tokens while keeping the old probabilities changes the learning problem.

We need two things at once: an exact record of each sampled action for training, and a re-rendered history for the next call. That is why one flat, append-only sequence is not always enough.

Why this is separate from tokenization drift
Retokenization can preserve every character while changing token IDs. Coercion changes the rendered history itself. Both can break prefix continuity; a successful rewrite uses the ordinary prefix check. Rejection is a terminal outcome with no next prompt. Only an attempted next compilation can reject.
Training eligibility still requires valid captured likelihoods, provenance and the correct original prompt. A matched coercion alone is not a reason to discard the action.

WHY THE CHEAPER DESIGN ISN’T READY
Sharing text is easy.
Sharing model state is harder.
Trunk-and-branch training could avoid much of the repeated work. But it needs new service and engine support. Our flagship model has recurrent attention and convolution state as well as ordinary attention.
Branching its token history also requires branching that state correctly. The proposed first engine path is limited to verified softmax-only models.

THE INTERPRETATION
Training-associated
doesn’t mean training-caused.
The held-out trained and base arms differ by about 1.55 percentage points in noncanonical-call rate. Standardizing by task, turn and response length reduces it to about 0.83 points, with an interval that includes zero.
Length and behavior also change after training. That adjustment is descriptive; it does not identify how much of the gap training caused.

How will we keep the conclusions honest?
Keep the adapter fixed where possible
A′ vs B changes serving memory while holding weights fixed. C vs B also changes the training run; one adapter per condition cannot establish a general training-method effect.
Respect the unit of evidence
Repeated samples from one task are related. The plan uses task-level uncertainty and a world-level check for the main deployment-gap claim. More draws are not more independent tasks.
Separate failure from missing data
A recorded policy failure is a zero under the evaluation convention. An unavailable grader or an unresolved infrastructure void has an unknown reward. Missing outcomes stay visible on the original task grid.
Choose the decision rule in advance
Superiority, non-inferiority and “no detectable difference” are different statements. The margin is fixed before outcomes; a noisy result does not earn a wider acceptable loss.

WHAT CHANGED DURING REVIEW
A final answer must stay final.
An unused next-prompt render must not discard a valid completed action. This was a concrete bug found in the first implementation review.
A compiler includes its inputs.
Changing a nested tool definition can change the next prompt. Tool schemas need their own fixed snapshot and identity.
Keep the whole diagnostic record.
A constant-reward task can be filtered out of the optimizer batch. Its generated attempts must still be saved for diagnostics and the pilot comparison.
Plan from the work that exists.
Scoring costs depend on actual prompt lengths and segment counts. Freeze each request family’s plan before its first request, then compare actual work with that plan.
